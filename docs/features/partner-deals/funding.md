# Deal funding integration

`partner_deals.attach_won_funding(member_id, deal_id)` is a private database seam called by the authenticated Won transition inside its transaction. It locks the deal, each cash contribution and season. It creates one secured sponsor-cash funding record per season, with finance audit and a freshness update. The function never marks funds received and ignores in-kind contributions. A failure raises and rolls back the complete transition. Retry preserves existing linked records.

A same-name existing sponsor-cash record in a covered season triggers `deal_funding_possible_duplicate`; confirming must stop and the notification should direct the user to Finance. POST `/api/partner-deals` with `action: linkFunding`, `contributionId`, and `fundingId` associates an existing exact matching source, season, amount and secured/received funding without changing it. The actor needs both deal-pipeline access and existing finance `manageFunding`. The paired `unlinkFunding` action removes a mistaken draft association without deleting financial data. Grant and identity checks happen within each transaction. A unique funding link prevents one finance record from funding two contributions. A closed season cannot be linked or automatically funded.

The existing funding selector and an actionable recovery control must be added by the UI integration before this workflow is complete. The duplicate rule conservatively blocks a second unlinked cash record from the same sponsor in one season; a workflow for two distinct agreements in that situation needs further product clarification. Future seasons must already exist; this seam does not configure a scheduler, create seasons, manage grants, send invoices, or alter partner portal access.
