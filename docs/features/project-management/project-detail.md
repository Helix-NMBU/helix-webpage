# Project detail view

Opening a project from the workspace directory or a department's filtered project list opens `/projects/:projectId`, defaulting to Issues. Overview shows its description and counts; Activity shows up to 50 recorded issue-status observations. Existing project-module access is required for issue details and activity. Directory-only members retain the public project properties and aggregate completion; the page does not infer a new task-module grant.

The Issues view groups this project's task-kind records by their existing statuses, including completed and cancelled issues. Milestones appear in the side widget with linked-task completion. Selecting one filters only the issue list; selecting it again clears that filter. Selecting another replaces it. The URL carries the selected milestone, including a `none` value for legacy work without milestone placement. Search combines with milestone filtering; clear controls restore the full issue list. Milestones from other projects cannot contribute issues. Empty milestones show an empty list while retaining the project context.

Properties shows status derived from the project's issues, stored priority, project Leads, issue assignees, target date, departments, work area and season. Project managers and the relevant department Leads edit project fields through the existing project form. Task creation, milestone creation, task editing and completion use the existing scoped task-Lead/assignee/manager permissions and authenticated project API. New issues preselect the active milestone when it is an available milestone in this project. Existing incomplete tasks remain under No milestone and can still use bounded status updates.

Progress remains scoped to the whole project while the issue list is filtered. Cancelled issues and milestone records are excluded from the completion denominator. The chart reuses observed task-status history, filtered to the project's current task IDs; it is not a historical record of project-membership changes. Deleted or moved tasks cannot be attributed to their former project using the current event schema. Scheduled dates do not fabricate history or forecasts. Activity records observations, not a complete audit of edits or authors.

Mutation responses immediately update the issue list, milestone counts and chart. Directory aggregate counts refresh after a task change. Failed writes preserve input; denied reads clear private issue state. No schema migration, new serverless function, hosted service change, external notification or new access grant is added by this view.
