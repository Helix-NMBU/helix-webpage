# Project detail view

Opening a project from the workspace directory or a department's filtered project list opens `/projects/:projectId`, defaulting to Tasks. Overview shows its description and counts; Activity shows up to 50 recorded task-status observations. Existing project-module access is required for task details and activity. Directory-only members retain the public project properties and aggregate completion; the page does not infer a new task-module grant.

The Tasks view groups this project's task-kind records by their existing statuses, including completed and cancelled tasks. Milestones appear in the side widget with linked-task completion. Selecting one filters only the task list; selecting it again clears that filter. Selecting another replaces it. The URL carries the selected milestone, including a `none` value for legacy work without milestone placement. Search combines with milestone filtering; clear controls restore the full task list. Milestones from other projects cannot contribute tasks. Empty milestones show an empty list while retaining the project context.

Properties shows status derived from the project's tasks, stored priority, project Leads, task assignees, target date, departments, work area and season. Project managers and the relevant department Leads edit project fields through the existing project form. Task creation, milestone creation, task editing and completion use the existing scoped task-Lead/assignee/manager permissions and authenticated project API. New tasks preselect the active milestone when it is an available milestone in this project. Existing incomplete tasks remain under No milestone and can still use bounded status updates.

Progress remains scoped to the whole project while the task list is filtered. Cancelled tasks and milestone records are excluded from the completion denominator. The chart reuses observed task-status history, filtered to the project's current task IDs; it is not a historical record of project-membership changes. Deleted or moved tasks cannot be attributed to their former project using the current event schema. Scheduled dates do not fabricate history or forecasts. Activity records observations, not a complete audit of edits or authors.

Mutation responses immediately update the task list, milestone counts and chart. Directory aggregate counts refresh after a task change. Failed writes preserve input; denied reads clear private task state. No schema migration, new serverless function, hosted service change, external notification or new access grant is added by this view.

## Task creation

The project view consistently calls work items Tasks, including tabs, search, status groups, milestone filters, progress text, access feedback and notifications. Legacy `tab=issues` links still resolve to the default Tasks view.

New task opens the shared creation modal with an always-visible title and description, pill controls for status, priority, multiple assignees, project, milestone and due date, and optional start date/type details. Partner work retains its required sponsor/partner field; Blocked work requires a blocked reason. The active milestone is preselected when available. Expand/restore and Create more controls work without changing the existing task model or permissions. Create more keeps the project, milestone and other attributes while clearing title/description and generating a new ID after a successful save. Failed saves preserve the draft and ID. The project parent leaves dismissal to the composer so Create more stays open.

On desktop, the project view fits the viewport below the shell breadcrumb. Project content and the Properties/Milestones/Progress column scroll independently, with overscroll contained at each column’s edges. Both scroll regions can receive keyboard focus. Mobile retains a stacked, page-scrolling layout.

Progress charts mark the stored project target date with a red vertical line and red hatching to its right. The date domain includes padding after the target so this region remains visible even for distant deadlines. An overdue deadline remains at its actual date; it is not moved to today. No red region is shown for an undated project. The overall Overview chart uses the latest project deadline. This shading indicates time after the deadline, not a forecast or a prediction of missed work.
